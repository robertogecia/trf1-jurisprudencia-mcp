### 1. [ALTA] `obter_decisao_trf1` devolve documento de OUTRO processo como se fosse o pedido

**Linhas 339 e 1190.**

```python
# 339
d["numero_digitos"] = next((_so_digitos(f) for f in formas if len(_so_digitos(f)) == 20), _so_digitos(d["numero"]))
# 1190
docs = [d for d in dados["docs"] if digitos in d["numero_digitos"] or d["numero_digitos"] in digitos]
```

Três falhas somadas no mesmo filtro:

1. **Documento sem campo "Número" ⇒ `numero_digitos == ""` ⇒ `"" in digitos` é sempre `True`.**
   Casa com qualquer número que o advogado peça.
2. **Número não-processual vira dígitos soltos.** "Súmula 12" ⇒ `numero_digitos == "12"`, e
   `"12" in <20 dígitos>` casa com toda CNJ que tenha "12" em qualquer posição. `obter_decisao`
   consulta `list(TIPOS_VALIDOS)` — **inclui SUMULA** —, então esse documento pode vir na resposta.
3. **Número curto (7 dígitos, o mínimo aceito na linha 1186) casa por prefixo com qualquer processo.**

E o pior: quando o filtro aceita lixo, `docs` fica não-vazio, então o aviso das linhas 1191-1193
("o portal devolveu documentos cujo número não bate exatamente — confira") **nunca dispara**. A saída
sai com cara de confirmada.

**Reprodução** (stub no lugar de `_consultar_portal`, sem rede):

```
$ python  # docs = [Súmula 12 parseada do HTML padrão do portal]
>>> srv._consultar_portal = fake          # devolve só a "Súmula 12"
>>> await srv._obter_decisao("0001234-56.2020.4.01.0000")
**1 documento(s) publicado(s) sob o número Súmula 12**

### Súmula · id 1 · julgado em ?
Citação: (TRF-1 - Súmula: Súmula 12)
```

Segundo caso, com um documento sem campo "Número":

```
>>> await srv._obter_decisao("0001369-17.2017.4.01.3606")
**1 documento(s) publicado(s) sob o número 0001369-17.2017.4.01.3606** (o portal informa 3; mostrando os primeiros)
### Súmula · id 2 · julgado em ?
Citação: (TRF-1 - Súmula: )
```

Uma súmula sem número nenhum aparece cabeçalhada com o número do processo do cliente, **sem aviso**.

**Correção proposta:**

```diff
-        docs = [d for d in dados["docs"] if digitos in d["numero_digitos"] or d["numero_digitos"] in digitos]
+        docs = [
+            d for d in dados["docs"]
+            if d["numero_digitos"] and (
+                d["numero_digitos"] == digitos
+                or (len(digitos) < 20 and d["numero_digitos"].startswith(digitos))
+            )
+        ]
```

Mata a casa vazia, mata a direção invertida (Súmula 12), e mantém a busca por número parcial só
como **prefixo**. Documento sem número passa a cair no ramo 1191-1193, que avisa — que é o
comportamento correto.

### 2. [ALTA] Ementa com "acesso bloqueado"/"suspeita de automação" arma o disjuntor por 10 min

**Linhas 929-933 (`_RE_BLOQUEIO`) e 990 (`_requisitar`).**

```python
eh_bloqueio = bool(_RE_BLOQUEIO.search(texto[:20_000]))
```

O teste é feito sobre os primeiros 20 KB da **resposta inteira**, que inclui as ementas. O padrão
`acesso (foi )?bloqueado|p[aá]gina bloqueada|robotiza|suspeita de automa` é vocabulário jurídico
comum (bloqueio de conta/SISBAJUD, acesso a sistema, robotização do serviço público).

O README diz que "captcha" já foi retirado por exatamente esse motivo; o mesmo problema sobreviveu
nos outros padrões.

**Alcance é real, não teórico.** Na resposta de **busca** a 1ª ementa começa no offset 21.310 (fora
da janela, por pouco). Na resposta de **paginação** (`04_pagina2.xml`) a 1ª ementa começa no offset
**6.092** — dentro da janela. E toda chamada de `obter_decisao_trf1` passa por paginação (usa
`por_pagina=50`, linha 1188, e a linha 1106 dispara a paginação sempre que `por_pagina != 30`).

**Reprodução** (uma palavra trocada na 1ª ementa real do fixture de paginação):

```
falso positivo (ementa) em texto[:20000]: True   -> match 'ACESSO BLOQUEADO'
'<partial-response' nos 2000 primeiros:  True    (resposta 200 legítima)
com 'SUSPEITA DE AUTOMACAO':             True
```

Consequência: `_registrar_bloqueio_detectado(subir_escada=True)` → `bloqueado_ate = agora + 600s`,
`backoff_s` dobra, `indice_janela` sobe um degrau, `sucessos = 0`. Dez minutos de servidor morto por
uma ementa. Vale para as duas ferramentas de rede.

**Correção proposta** (testar só o **envelope**, fora do CDATA — a ementa sempre vem dentro dele; a
página do Cloudflare não tem CDATA nenhum):

```diff
+def _envelope(texto: str) -> str:
+    """Resposta sem o conteúdo dos CDATA: as ementas vivem lá dentro, e 'acesso bloqueado' /
+    'sessão expirada' ali são texto de acórdão, não sinal do portal."""
+    e = re.sub(r"(?s)<!\[CDATA\[.*?\]\]>", " ", texto or "")
+    return e.split("<![CDATA[")[0][:20_000]   # CDATA aberto = resposta cortada
@@ async def _requisitar(...)
-    eh_bloqueio = bool(_RE_BLOQUEIO.search(texto[:20_000]))
+    envelope = _envelope(texto)
+    eh_bloqueio = bool(_RE_BLOQUEIO.search(envelope))
```

**Verificado** (mesma sessão offline):

```
falso positivo ementa (paginação) ANTES: True | DEPOIS: False
Cloudflare real (07_arquivo_menu.html):  True   (continua detectado)
regressão em todos os 6 fixtures:        OK
custo: 2,8 ms por resposta de 368 KB
```

### 4. [MÉDIA] `[EMEN]`/`[DECI]`/`[REL]` dentro de `grupos` viram busca literal — e o README ensina a usar

### 5. [MÉDIA] `_RE_CAMPO` quebra com `<td>` que tenha atributo — e apaga TODOS os campos em silêncio

**Linhas 300-303.**

```python
r'<span class="label_pontilhada">\s*(.*?)\s*</span>\s*</td>\s*</tr>\s*<tr>\s*<td>(.*?)</td>'
```

O `<td>` do **valor** precisa ser literal, sem atributo. O portal já usa `<td class="titulo_doc">`,
`<td colspan="2">` e `<td role="gridcell">` em outros pontos do mesmo HTML — um redeploy que
acrescente uma classe ao `<td>` do valor derruba o parser inteiro.

O modo de falha não é "nenhum resultado": é **resultado com metadado vazio**, porque o `.*?` do
rótulo atravessa o bloco e produz um campo-fantasma:

```
>>> srv._parsear_documentos(html_com_td_class)[0]
relator= ''  ementa= ''  campos= ['Relator(a) FULANO Ementa']
```

O documento continua sendo emitido e formatado — com citação `(TRF-1 - Julgado: )`. Sem aviso.

**Mesmo bug, segunda cara:** `(.*?)</td>` para no **primeiro** `</td>`. Uma tabela dentro da ementa
trunca a ementa em silêncio — e `obter_decisao_trf1` promete "ementa INTEGRAL, literal do portal":

```
ementa fonte:  'PARTE A <table><tr><td>celula</td></tr></table> PARTE B FINAL'
ementa parseada: 'PARTE A celula'      # "PARTE B FINAL" sumiu
```

*(Nos 30 fixtures reais nenhuma ementa contém `<td>`/`<table>` — só `font` e `b`. A ocorrência é
hipótese; o mecanismo é confirmado.)*

**Correção proposta** (ancorar no fechamento do `<div class="ui-outputpanel">` que envolve cada par):

```diff
 _RE_CAMPO = re.compile(
-    r'<span class="label_pontilhada">\s*(.*?)\s*</span>\s*</td>\s*</tr>\s*<tr>\s*<td>(.*?)</td>',
+    r'<span class="label_pontilhada">\s*(.*?)\s*</span>\s*</td>\s*</tr>\s*'
+    r'<tr[^>]*>\s*<td\b[^>]*>(.*?)</td>\s*</tr>\s*</div>',
     re.S,
 )
```

**Verificado contra o fixture real**: 362 pares com a regex atual, **362 pares idênticos** com a
nova (mesmos rótulos, mesmos valores). E resolve os dois casos sintéticos acima.

### 6. [MÉDIA] `_resultado_de` não cobre formas correntes de dispositivo do TRF1

**Linhas 404-414.** Rodei `_resultado_de` nos **60 dispositivos reais** de
`02_busca_dano_moral.xml` + `04_pagina2.xml`. 49 classificam bem; 11 caem em "sem resultado".
Desses, o comportamento conservador está certo em 4 (apelações com resultados opostos — #2, #4, #21,
#41) e é **lacuna de vocabulário** nos outros.

Lacunas confirmadas por execução (todas devolvem conjunto vazio):

```
'conhecer do agravo e dar-lhe provimento'   -> {'CONHECIDO'}  (o provimento se perde)
'negar-lhe provimento'                      -> set()
'dar integral provimento à apelação'        -> set()
'dar-lhes provimento'                       -> set()
'prover a apelação' / 'não prover'          -> set()
'negar seguimento ao agravo'                -> set()
'julgar procedente/improcedente'            -> set()
'conceder parcialmente a ordem de HC'       -> set()   (caso real #49 do fixture)
'denegar a segurança'                       -> set()
'declarar a incompetência deste Tribunal'   -> set()   (caso real #30)
```

Causa: `_RE_PROVIDO` exige `D(A|AO|AR|OU|ERAM|EU)(-SE| SE)? (PARCIAL )?PROVIMENTO`, que não aceita
`-LHE`/`-LHES` nem o advérbio `INTEGRAL`; e `_RE_DESPROVIDO` exige `NEG\w*(-SE| SE)? PROVIMENTO`,
que não aceita `NEGAR-LHE PROVIMENTO`.

Um segundo efeito, também confirmado: uma preliminar rejeitada derruba um resultado claro para
"sem resultado", porque os dois pares de `_OPOSTOS` acendem ao mesmo tempo.

```
'dar provimento à apelação, rejeitada a preliminar' -> lados=['PROVIDO','REJEITADO'] -> sem resultado
'negar provimento, acolhida em parte a preliminar'  -> lados=['DESPROVIDO','ACOLHIDO'] -> sem resultado
```

**Correção proposta** (mínima, só o que os textos confirmam; não invento vocabulário que não vi):

```diff
 _RE_DESPROVIDO = re.compile(
-    r"\b(DESPROVI|IMPROVI|NAO PROVI|NEG\w*(-SE| SE)? PROVIMENTO|PROVIMENTO NEGADO)", re.ASCII
+    r"\b(DESPROVI|IMPROVI|NAO PROVI|NEG\w*(-(SE|LHE|LHES)| SE)? (INTEGRAL |PARCIAL )?PROVIMENTO"
+    r"|PROVIMENTO NEGADO)", re.ASCII
 )
 _RE_PROVIDO = re.compile(
-    r"(?<!NAO )\b(PROVI(DO|DOS|DA|DAS)\b|D(A|AO|AR|OU|ERAM|EU)(-SE| SE)? (PARCIAL )?PROVIMENTO)", re.ASCII
+    r"(?<!NAO )\b(PROVI(DO|DOS|DA|DAS)\b"
+    r"|D(A|AO|AR|OU|ERAM|EU)(-(SE|LHE|LHES)| SE)? (INTEGRAL |PARCIAL )?PROVIMENTO)", re.ASCII
 )
```

O caso "preliminar rejeitada" é de desenho, não de regex: se quiser resolver, priorize o par
PROVIDO/DESPROVIDO sobre ACOLHIDO/REJEITADO quando os dois acenderem — mas isso é decisão sua,
não conserto óbvio. Deixo apontado, não corrigido.

### 8. [MÉDIA] Orçamento de requisições subdeclarado: `obter_decisao_trf1` custa **4**, não "2 a 3"

**Linhas 791, 859, 1068-1117, 1188 e README §"Ritmo e bloqueio".**

Caminho de `_obter_decisao` (`por_pagina=50`, `avancados={"numero": …}`):

| # | requisição | linha |
|---|---|---|
| 1 | GET inicial (sessão + ViewState) | 1084 |
| 2 | POST toggle da avançada (porque `avancados` é truthy) | 1090 |
| 3 | POST busca | 1096 |
| 4 | POST paginação (linha 1106: `por_pagina != 30` ⇒ sempre verdadeiro aqui) | 1111 |

Uma busca com filtro e página 2 também custa 4. Com `por_pagina=10` (o valor usado no selftest
online) custa 3. Só a busca sem filtro, página 1, 30 por página custa 2.

E `_reservar_requisicao` (773) reserva **uma vaga por requisição**, não as N da operação — com o teto
em 24, a 24ª vaga pode ser consumida no meio de uma operação: a sessão fica aberta no portal e o
usuário recebe "Muitas consultas em pouco tempo" com 2 ou 3 requisições já gastas à toa. Somado à
retentativa do achado 3, uma única chamada pode custar **8** requisições.

**Correção proposta** — mínima, de honestidade: trocar "2 a 3" por "2 a 4" nas linhas 791, 859 e no
README. A correção de fundo (reservar as N vagas de uma vez, com devolução no fim) é maior e não é
óbvia num servidor cujo estado é compartilhado entre processos; registro como decisão sua, não como
conserto pendente.

### 9. [MÉDIA] Se `total` vier 0 com documentos na página, a paginação é pulada e a página 1 é servida como página N

**Linhas 286-296 (`_extrair_total`), 1106 e 503-608.**


Com `total == 0`, o ramo inteiro é pulado e `html_docs = html_form` — isto é, **os documentos da

(o item numerado 31 é o **primeiro** da página 1). Nenhum aviso.

faltem todos na resposta de busca — não observado nos fixtures, logo a **ocorrência é hipótese**; o
comportamento acima é confirmado por execução de `_format_busca`.

**Correção proposta:**

```diff
-            if total and (first > 0 or por_pagina != 30):
```

### 12. [BAIXA] `_citacao` de resultado que não seja "TRF - PRIMEIRA REGIÃO"

**Linha 471.** A lógica está certa para o caso confirmado (`"TRF - PRIMEIRA REGIÃO"` → `TRF-1`, e
origem vazia → `TRF-1`), mas quando a origem é outra ela vira o **prefixo do tribunal** na citação:

```
origem='TURMA RECURSAL - RO'          -> (TURMA RECURSAL - RO - AC: …)
origem='SEÇÃO JUDICIÁRIA DE RONDÔNIA' -> (SEÇÃO JUDICIÁRIA DE RONDÔNIA - AC: …)
```

Nos 60 documentos dos fixtures a origem é **sempre** `TRF - PRIMEIRA REGIÃO` (0 casos JEF1), então o
que a fonte JEF1 devolve em "Origem" é desconhecido. Se for a seção judiciária, a citação sai com um
prefixo que não é nome de tribunal. Sugestão sem risco: manter `TRF-1` como prefixo sempre e mover a
origem para um segmento próprio (`… , Origem: TURMA RECURSAL - RO, …`), como já é feito no corpo do
resultado na linha 555-556.

## HIPÓTESES (não confirmadas — exigem teste online)

1. **`_extrair_total` com ACORDAO+SUMULA juntos.** Não há fixture com dois tipos. Pelo HTML do
   DataGrid (um único widget `formulario:tabelaDocumentos` com um `rowCount`), o esperado é **um**
   `rowCount` com o total somado, e nesse caso `re.search` pegar o primeiro está certo. O fallback
   dos contadores (linha 292-294) **soma** todas as ocorrências — se o portal imprimir um contador
   por tipo, a soma acerta; se imprimir o total e um subtotal, dobra. Não dá para decidir offline.
2. **`consulta` livre não é escapada** (linha 253). Confirmado que passa crua:
   `_montar_consulta("dano moral; drop", None)` → `'dano moral; drop'`;
   `_montar_consulta("(dano moral", [["x"]])` → `'((dano moral) E x'` (a moldura dos grupos **piora**
   o desbalanceamento). O que o motor BRS do CJF devolve nesses casos — erro em `j_idt16:messages`,
   zero resultados, ou resultado silenciosamente errado — é exatamente o que não posso testar.
   Se vier erro em `messages`, a linha 1099-1101 já o repassa bem.
3. **Ementa/decisão com `<table>` embutida** (achado 5, segunda cara). 0 de 30 ementas dos fixtures
   têm `<td>`; a truncagem é confirmada, a ocorrência não.
4. **`formulario:tabelaDocumentos_rppDD`** no form de paginação (linha 1061) não consta do protocolo
   confirmado (§3.1); §3.3 diz que trocar rows-per-page é `[NÃO TESTADO]` e sugere que o
   `javax.faces.source` deveria ser o próprio `<select>`. `por_pagina=10` funcionou hoje, `50`
   (usado por toda chamada de `obter_decisao_trf1`) não está confirmado — se o portal ignorar e

5. **`_extrair_update` para no primeiro `]]>`** (linha 261). O Mojarra quebra o CDATA em
   `]]]]><![CDATA[>` quando o conteúdo contém `]]>`. Texto de acórdão com `]]>` é improvável, mas o

## O que tentei quebrar e resistiu

- **Estado real do disjuntor durante o `--selftest`.** Conferi `stat` + `diff` de
  `.disjuntor_estado_trf1.json` antes e depois: **byte a byte idêntico**. A troca do
  `globals()["_ARQUIVO_ESTADO_DISJUNTOR"]` na linha 1467 acontece antes de qualquer
  `_reservar_requisicao`, e o `_limpar_estado()` da linha 1555 roda **antes** do swap de volta, então
  apaga o temporário, não o real. Suspeita 16 refutada.
- **`tipo="ACORDAO"` como string** (suspeita 15). O Pydantic do FastMCP recusa antes de chegar ao
  código: `Input should be a valid list [type=list_type]`. A iteração por caractere de
  `_validar_tipos` só é alcançável em chamada direta — a mensagem fica feia
  (`tipo inválido: ['A','C','O','R','D','A','O']`) mas não é caminho de produção.
  Schema de `grupos` gerado corretamente como `array[array[string]] | null`.
- **`pagina`/`por_pagina` como string.** O schema declara `integer`, e mesmo assim `int(pagina or 1)`
  e `int(por_pagina or 30)` tratam `"2"`, `30.0`, `""` e `None`. `"trinta"` levanta `ValueError`, que
  cai no `except` da linha 1174 e vira mensagem, não stack trace.
- **`_limpar` com limite e texto sem espaço:** `_limpar("A"*50, 10)` → `'AAAAAAAAAA…'` (o
  `rsplit(" ", 1)` degrada bem). `_limpar("«»", 5)` → `'«»'`.
- **`_RE_SIGLA_CLASSE`:** acerta `(AG)`, `(RSE)`, `(HC)`, `(REOMS)`, tolera espaço à direita, e
  devolve `None` (com fallback para a classe inteira) em `"APELAÇÃO CÍVEL"` sem sigla.
- **Numeração de `_format_busca` com `por_pagina` diferente:** página 3 × 10 por página começa em
  **21**, correto. Sem "Próxima página" quando `total` é 0. `total_paginas` com 10/1124 → 113.

- **Rótulo desconhecido no bloco** (`"Assunto novo"`): preservado em `d["campos"]` e exibido por
  `_format_decisao`; rótulo repetido mantém o primeiro. Como documentado.
